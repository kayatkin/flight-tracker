# Руководство по внесению изменений

Спасибо за интерес к проекту Flight Tracker!

## Как внести изменения

### 1. Создание issue

- Проверьте, нет ли уже существующего issue с такой же проблемой/предложением
- Опишите проблему или предложение максимально подробно
- Для багов укажите: шаги воспроизведения, ожидаемое и фактическое поведение, скриншоты
- Используйте шаблоны issue (если настроены)

### 2. Ветвление

```
main — основная ветка (production)
  └── feat/название-фичи    — новая функциональность
  └── fix/название-бага     — исправления
  └── refactor/что-меняем   — рефакторинг
  └── docs/что-добавляем    — документация
```

Создавайте ветку от `main`:

```bash
git checkout -b feat/название-фичи main
```

### 3. Разработка

#### Стиль кода

Проект использует TypeScript. Придерживайтесь следующих правил:

- **Именование**: camelCase для переменных/функций, PascalCase для компонентов/типов
- **Компоненты**: один компонент на файл, CSS Modules для стилей
- **Импорты**: используйте path aliases (`@shared/utils`, `@features/flights`)
- **Типы**: явные типы для параметров функций, избегайте `any`
- **Форматирование**: 2 пробела для отступов, точка с запятой в конце

#### Структура компонента

```
ComponentName/
├── ComponentName.tsx          # Код компонента
├── ComponentName.module.css   # Стили
├── index.ts                   # Реэкспорт
└── components/                # Вложенные компоненты (опционально)
```

#### Тесты

- Тесты обязательны для утилит в `shared/utils/`
- Файл теста: `__tests__/moduleName.test.ts`
- Используйте `describe` / `it` / `expect`
- Покрывайте граничные случаи

```bash
npm test                     # запуск всех тестов
npm test -- --watch         # в режиме watch
```

### 4. Коммиты

Формат: `<тип>: <описание>`

Типы:
- `feat` — новая функциональность
- `fix` — исправление бага
- `refactor` — рефакторинг
- `style` — стили, форматирование
- `docs` — документация
- `test` — тесты
- `chore` — рутинные задачи

Примеры:
```
feat: добавлен экспорт истории в CSV
fix: исправлена валидация дат для roundTrip
refactor: вынесена логика цен в flightAnalysis.ts
docs: обновлён README с инструкцией по деплою
test: добавлены тесты для getSeasonalChartData
```

### 5. Pull Request

1. Убедитесь, что код собирается: `npm run build`
2. Убедитесь, что тесты проходят: `npm test`
3. Опишите изменения в PR: что сделано, почему, как протестировать
4. Свяжите PR с issue (если есть): `Closes #номер`
5. Дождитесь review

### 6. Проверки CI

При создании PR автоматически запускаются:

- Линтинг (ESLint)
- Сборка (`npm run build`)
- При пуше в `main` — деплой на GitHub Pages

## Настройка окружения

```bash
# 1. Клонировать репозиторий
git clone git@github.com:kayatkin/flight-tracker.git
cd flight-tracker

# 2. Установить зависимости
npm install
cd bot && npm install && cd ..

# 3. Создать .env.local
cp .env.example .env.local
# → заполнить значения (см. README.md)

# 4. Запустить
npm start
```

## Структура проекта (кратко)

| Директория | Назначение |
|-----------|-----------|
| `src/features/` | Фича-модули (flights, sharing, guest-mode) |
| `src/shared/` | Переиспользуемый код (hooks, utils, ui, types) |
| `src/services/` | Бизнес-логика (dataService, appInitService) |
| `bot/` | Telegram бот (Node.js) |
| `.github/workflows/` | CI/CD (деплой) |

Подробнее в [ARCHITECTURE.md](./ARCHITECTURE.md).

## Куда обращаться

- **Вопросы**: создайте issue с лейблом `question`
- **Баги**: issue с лейблом `bug` и шагами воспроизведения
- **Предложения**: issue с лейблом `enhancement`
- **Обсуждение**: Telegram-чат проекта (если настроен)
